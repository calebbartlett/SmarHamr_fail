Understanding Perchance Structure

These short statements explain how Perchance AI actually organizes characters, worlds, threads, lore, and memory. Knowing this helps you use SmarHamr effectively.

Characters are assets.

Characters are reusable definitions. They do not store memories. They do not store lore. They do not store conversations.

Threads are sessions.

A thread is where the conversation happens. Threads store messages, summaries, memories, and user history. Threads also store thread‑specific lore.

Threads are rooted in assets.

A thread begins by selecting a character or a world. The asset becomes the “root” of the thread. The thread inherits the asset’s instructions and context.

Lore is thread‑specific.

Lore does not travel with characters. Lore belongs to the thread. Each thread has its own lore text.

Memories are thread‑specific.

Memories do not travel with characters. Memories belong to the thread. Each thread has its own memory list.

Worlds are assets.

A world defines global lore, rules, tone, and culture. Threads can be rooted in a world asset. Worlds do not store thread memories.

Assets define. Threads run.

Assets = definitions. Threads = runtime containers. Dexie = the database that stores both.

SmarHamr helps you work with both.

Character‑Centric Mode edits character‑rooted threads. World‑Centric Mode edits world‑rooted threads. Dexie Editor edits the raw database.
